## Architecture

You already own everything this needs. Nothing here costs money.

```text
  ┌──────────────────────┐
  │  M5 MacBook Pro      │  control plane, browser, KQL
  └──────────┬───────────┘
             │
  ┌──────────┴───────────┐        ┌─────────────────────┐
  │  VMware Fusion       │        │  Microsoft Sentinel │
  │  ┌────────────────┐  │        │  (Azure free tier)  │
  │  │ Windows 11 VM  │──┼───────▶│  Log Analytics WS   │
  │  │ + Sysmon       │  │  AMA   │                     │
  │  └────────────────┘  │        └─────────────────────┘
  │  ┌────────────────┐  │
  │  │ Kali ARM64     │  │  attacker box
  │  └────────────────┘  │
  └──────────┬───────────┘
             │
  ┌──────────┴───────────┐
  │  Raspberry Pi 4B     │  isolated lab network, OpenWrt
  │  OpenWrt router      │  keeps lab traffic off the home LAN
  └──────────────────────┘
```

<Callout type="warn">
**Cost control matters more than anything else here.** Azure's free tier plus the
Sentinel trial is generous, but an unattended data connector on a chatty VM can
burn through it. Set a budget alert at £5 on day one, before you connect
anything. Cap your daily ingestion in the workspace. Do this first — people who
skip it get a bill and abandon the lab.
</Callout>

<Lab title="Stand up the pipeline" host="M5 + VMware Fusion" minutes={300}>

**1 — Azure and workspace.** Create a free Azure account. Create a Log Analytics
workspace in UK South. Set the daily cap to 500 MB and add a budget alert at £5.
Enable Microsoft Sentinel on the workspace.

**2 — Windows VM.** Windows 11 Evaluation in VMware Fusion, 4 GB RAM, on the
Pi's isolated network. Join it to nothing; a standalone box is enough for now.

**3 — Audit policy.** Before installing anything, turn on the logging that is off
by default:
- Audit Process Creation → Success
- "Include command line in process creation events" → Enabled
- Audit Logon / Logoff → Success and Failure
- Audit Object Access for the shares you care about

Confirm 4688 now carries a command line. If it doesn't, stop and fix it — every
later detection depends on it.

**4 — Sysmon.** Install with a tuned config:
```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig-export.xml
```
Verify events land in `Applications and Services Logs → Microsoft → Windows → Sysmon`.

**5 — Ship the logs.** Install the Azure Monitor Agent on the VM and create a
Data Collection Rule that gathers Security events and the Sysmon channel. Be
selective: collect the events from your Phase 1 list, not everything.

**6 — Prove it end to end.** On the VM, run something distinctive:
```powershell
powershell.exe -enc VwByAGkAdABlAC0ASABvAHMAdAAgACIAdABlAHMAdAAiAA==
```
Then in Sentinel:
```kql
SecurityEvent
| where TimeGenerated > ago(15m)
| where EventID == 4688
| where CommandLine has "-enc"
| project TimeGenerated, Computer, Account, NewProcessName, CommandLine
```
When that returns your row, the pipeline works. **Screenshot it.**

</Lab>

## What "done" means

Not "it's running." Done means you can answer these without checking:

- Which events am I collecting, and what did I deliberately leave out?
- What does my daily ingest look like, and what's my cap?
- If a detection fired right now, could I get from alert to raw event in under a minute?
- What is my blind spot? (There is one. Name it.)

That last question is the interview question. Everyone builds a lab; almost
nobody can articulate what their own telemetry cannot see.
